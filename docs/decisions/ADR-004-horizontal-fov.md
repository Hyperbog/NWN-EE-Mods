# ADR-004 — Horizontal FOV and modern first-person conventions

Status: Accepted; first horizontal-FOV patch integrated, build and gameplay validation pending.

Owner: express FOV horizontally to align with modern FPS conventions; align future changes with modern conventions. This supplements ADR-002 animation-aware eye, ADR-003 input/menu/tracking and single intended EFP experience. No universal claim that all modern games use horizontal FOV.

Player-facing first-person FOV shall mean actual horizontal viewing angle. Engine/Alloy projection continues to consume vertical degrees; convert at the correct camera boundary using v = 2 atan(tan(h/2)/aspect), with actual world viewport aspect (radians internally). No postprocessing warp or nonlinear projection proposed. 90 horizontal at 2560x1440 yields 58.7155 vertical; old 90 vertical yields 121.2845 horizontal. Do not merely relabel the old slider. Proposed default 90 horizontal, no advanced/alternate FOV toggle. Exact supported range, config migration and viewport validity/resizing policy must be reviewed before code. Preserve previous config/rollback; do not silently reinterpret stored vertical values or reset unrelated settings. Explicitly communicate old/new semantics; recommend a clearly versioned first-person setting and documented migration, separate from unrelated third-person/free-camera behavior. Verify actual aspect across native and Alloy paths, no guessed permanent aspect, and unchanged projection/picking/reticle coherence; test 4:3, 16:9 and ultrawide, resize, gates, dialogue and jumping. Existing CameraService and FreeCameraService consume vertical angles; do not inadvertently convert twice. Modern conventions guide future input, UI, camera and movement decisions but not justification for speculative rewrites or server-authority violations.

Jump discontinuity is separately evidenced by [diagnostic results](../testing/RESULTS/2026-11-27-M11-jump-framing.md). Recommended sequence: isolated horizontal FOV implementation and validation, then isolated jump-eye continuity correction using existing diagnostic. #12 remains queued. No runtime change in this decision commit.
