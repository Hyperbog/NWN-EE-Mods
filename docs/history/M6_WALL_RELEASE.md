No 0x06/0x21 abort send was logged for release id 4; an earlier explicit abort used that existing opcode with bytes=0. This is evidence of a persistent rejected drive, not proof of server acknowledgement or a general animation defect.

M6 changes only StepGuardService and CameraDriveService. It tracks consecutive rejected native steps and a real keyboard release. After at least 150 ms of recent repeated collision refusals with all keys up and the same drivable local player/area, it sends the already-used abort message once, following native UpdateDriveMode. Accepted movement resets refusal tracking; input, camera-mode/modal changes, player/area changes, or native drive clearing invalidate recovery. No direct animation writes, new packet types, collision-radius changes, speed changes or server position changes are added. An explicit abort already sent by the existing path suppresses the fallback. The fallback log marker is [m6wall]. The send is an attempt, not a guarantee of server acceptance. Native build and gameplay remain pending. Rare angle-dependent camera/model clipping is deliberately deferred because the current trace does not identify its cause.
